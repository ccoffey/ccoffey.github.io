# Repository maintenance

This repository deliberately tracks the optimized source media needed to build
the published portfolio. A normal clone is therefore sufficient to build and
run a complete copy of the site; Git LFS is not required.

## What belongs in Git

- Source code, templates, tests, documentation, and `build.json` files.
- Optimized project media in `src/major-builds/*/media/` and
  `src/quick-builds/*/media/`.
- Reviewed visual-test baselines and small documentation images.

Generated `_site/` output, thumbnail/poster directories, test artifacts,
dependency directories, and local editor files do not belong in Git. They are
ignored and regenerated by the build.

## Adding media responsibly

The tracked pre-commit hook optimizes staged project media and removes JPEG
metadata. CI verifies the same limits:

- Images: at most 2560 pixels on their longest edge and 2.5 MiB.
- Videos over 25 MiB: re-encoded by the media optimizer before they are
  committed.

Keep the complete project source in Git when it is needed to reproduce the
site. For long raw footage, keep the editable original outside this repository
and commit a short, web-ready clip instead. Never commit generated thumbnails,
posters, duplicate exports, or `_site/` output.

## Inspecting local repository weight

Use these read-only checks when investigating an unexpectedly large clone:

```bash
git count-objects -vH
git rev-list --objects --all |
  git cat-file --batch-check='%(objecttype) %(objectsize) %(rest)' |
  sort -k2 -nr | head -20
```

To compact only unreachable local objects after confirming that no worktree,
branch, or stash needs them:

```bash
git gc --prune=now
```

This does not change commits, branches, or the remote repository.

## Published history

Do not rewrite `master` merely to make a clone smaller. A force-push breaks
forks, open pull requests, and existing clones. If a credential, private file,
or accidentally committed large binary must be removed from published history,
treat it as an incident: rotate any exposed credential, agree the exact paths
and replacement history, perform a separately reviewed `git filter-repo`
rewrite, force-push only after explicit approval, and ask collaborators to
re-clone.
