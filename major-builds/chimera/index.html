Chimera

A custom ESP32 handheld computer, a solid foundation for a secure messaging channel

ESP32 ESP-IDF Embedded C++
Build Demonstration

The Build Story

Before building Chimera, I had already built a private messaging server and Android app (which I called TwinChat) so that my brother and I could have secure conversations without relying on Meta's WhatsApp, which we were using prior to this.

The cryptographic setup was fairly straightforward: each of us had a public/private key pair, with the private key never leaving the Android device. We used a Diffie–Hellman key exchange with our public keys to establish a shared conversation key, routing encrypted payloads through a Dropwizard RESTful web service hosted on an Ubuntu server in my home office. I recreated all the WhatsApp features we loved: emoji reactions, GIFs, quote and respond, and even photo sharing (which were also transmitted as securely encrypted blobs).

My brother and I used TwinChat daily for about a year until he broke his personal phone and switched to a locked down work phone that blocked sideloading unpublished APKs outside the Google Play Store. Booo. Losing our private channel sparked an idea: what if we built our own dedicated hardware communicator that could run TwinChat? Our own app running on our own hardware. It could start as a simple, pocketable device inspired by the Nokia 3210s that we had in secondary school, many many years ago.

That was the spark, but building a standalone communicator took much longer than anticipated since I ended up having to write an entire embedded operating system from scratch first. I created a dynamic status bar with battery and WiFi indicators, along with a full WiFi manager that scans for SSIDs, accepts credentials, persists them to flash storage, and automatically reconnects when known networks are in range. Then came device settings for audio volume and screen brightness, followed by a PIN to unlock security layer.

Next, I needed to dial in the primary input: a single rotary encoder with a push button. To refine the interaction model, I built a native clone of Nokia's Snake. Naturally, an arcade game demanded 8 bit audio for sound effects and background music, followed by flash persistence for high scores.

To ensure the hardware was tamper resistant, I went deep into ESP32 silicon security: provisioning Secure Boot and Flash Encryption. I also knew we needed seamless over-the-air (OTA) updates—flashing both devices over USB during rapid development would quickly become a pain. Rather than risk embedding sensitive GitHub credentials in device flash, I designed a secure update pipeline: the source repository is private, and releases are brokered through a Cloudflare Worker proxy. Chimera connects over TLS 1.3 (validated against Mozilla's root CA bundle once clock-synced via NTP) with a pre-shared device secret header. The worker authenticates with GitHub using an edge-encrypted PAT, caches release assets to protect API limits, and streams the binary down into Chimera's inactive OTA slot with SHA-256 validation and hardware rollback protection. Moving to the latest firmware just requires a standard reboot.

Chimera is still a work in progress. Now that the hardware and OS foundation are rock solid, I'm finally back to building the messaging client itself. Stay tuned.
